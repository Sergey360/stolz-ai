**STOLZ** отсылает к Андрею Ивановичу Штольцу — деятельному герою романа Ивана Гончарова «Обломов».

В **A.I.** соединились инициалы героя (*Andrei Ivanovich*) и *Artificial Intelligence*.

> «Движений лишних у него не было».
>
> — [Иван Гончаров, «Обломов», часть II](https://ilibrary.ru/text/475/p.13/index.html)

Проект следует тому же принципу: **каждый токен должен выполнять полезную работу**.

## 🎯 Что именно экономится

STOLZ A.I. — это пять небольших, сочетаемых навыков для Codex и совместимых сред программных агентов:

- 🧭 **Маршрут** — выбрать один достаточный путь вместо загрузки всех инструкций;
- 📖 **Контекст** — читать только тот контекст, который нужен выбранному пути;
- ♻️ **Повторное использование** — использовать результат повторно, лишь пока совпадают его входы и проверка;
- 🔕 **Тихое состояние** — держать неизменившееся состояние опроса вне диалога с моделью;
- ⚖️ **Бенчмарк** — сравнивать оптимизацию с исходным вариантом, прежде чем считать её улучшением.

Эти механизмы сокращают лишний контекст, чтения, вызовы инструментов и повторные сообщения о состоянии. Они не требуют от модели думать меньше или пропускать проверки.

## 📊 Что уже доказано

Включённый синтетический сценарий выбора контекста достигает того же проверенного результата при меньшем объёме подготовленных входных данных:

| Маршрут | Подготовленные единицы токенов | Активации модели | Вызовы инструментов | Проверка |
| --- | ---: | ---: | ---: | --- |
| Исходный | 1 530 | 4 | 8 | пройдена |
| Оптимизированный | **980** | **3** | **4** | пройдена |
| Разница | **−550 (−35,95%)** | −1 | −4 | результат эквивалентен |

Это доказывает, что бенчмарк и маршрут с узким контекстом работают на данном сценарии. Это **не** измерение расхода Codex и **не** заявление об экономии во всех производственных задачах. У STOLZ A.I. пока нет измеренного утверждения о токенах провайдера. Доказательства и границы их интерпретации описаны в разделе [о бенчмарках](docs/benchmarking.md).

### Доказательства для нескольких сред в v0.7

STOLZ A.I. сохраняет очищенные доказательства уровня C2 только для Claude Code 2.1.251 и Qwen Code 0.22.3 с адаптером 1.0.0. Для Codex CLI 0.153.4 проверены четыре локальных запуска, но отдельной строки C2 в v0.7 нет. Допуск C3 реализован по принципу fail-closed, и все текущие пары провайдеров остаются `withheld`. Смена версии, отсутствие экспортов, несовпадение результатов или небезопасные данные требуют новой проверки.

Доказательства относятся только к конкретному сценарию. Они не подтверждают общие проценты экономии, стоимость, превосходство провайдера или универсальное преимущество.

Установка копирует пять навыков и выбирает профиль с ленивым адаптером. Она не запускает фоновую службу, общий кеш, постоянное хранилище состояния или автоматический контроллер опроса.

## 🚀 Установка

Codex обнаруживает навыки репозитория в `.agents/skills`. Из каталога вашего проекта:

```bash
git clone https://github.com/Sergey360/stolz-ai.git ../stolz-ai
npm --prefix ../stolz-ai ci
npm --prefix ../stolz-ai test
mkdir -p .agents/skills
cp -R ../stolz-ai/skills/stolz-* .agents/skills/
```

После этого упомяните `$stolz-route` в Codex или позвольте Codex выбрать навык, когда задача соответствует его описанию. Установка для Claude Code, Qwen Code, Windows и на уровне пользователя описана в [руководстве по установке](docs/installation.md).

В публичном архиве v0.13 есть CLI `stolz-profile`: он создаёт проверяемый
командный lock, завершает CI с ошибкой при расхождении конфигурации, раздельно
показывает совместимость среды и доступность ленивого адаптера, а также
поддерживает обновление, восстановление прерванной операции и откат. Инструкции
и проверочный сценарий чистого потребителя входят в тот же архив; доступ к
приватному репозиторию не нужен.

```bash
npm install --save-dev /absolute/downloads/stolz-ai-0.13.0.tgz
npx --no-install stolz-profile lock --apply --runtime codex --lockfile /absolute/project/stolz-profile.lock.json
npx --no-install stolz-profile verify-lock --runtime codex --lockfile /absolute/project/stolz-profile.lock.json
```

## 🧰 Пять навыков

| Навык | Когда использовать |
| --- | --- |
| [`stolz-route`](skills/stolz-route/SKILL.md) | неясно, какую оптимизацию выбрать или как применить fallback |
| [`stolz-context`](skills/stolz-context/SKILL.md) | нужно проверить существующий манифест контекста STOLZ или запись журнала чтений |
| [`stolz-reuse`](skills/stolz-reuse/SKILL.md) | уже существует прежний результат для допуска или одинаковая выполняющаяся команда для объединения |
| [`stolz-quiet-state`](skills/stolz-quiet-state/SKILL.md) | опрос или повторы иначе будут снова сообщать неизменившееся состояние |
| [`stolz-benchmark`](skills/stolz-benchmark/SKILL.md) | изменение эффективности требует сравнения при эквивалентном результате |

Известную задачу направляйте сразу нужному навыку; обычная работа с кодом не
требует маршрута STOLZ. Справочники загружаются по условиям выбранного навыка.
Обычное первое чтение не включает `stolz-context`, а отсутствие прежнего
результата не включает `stolz-reuse`. В v0.12 установленный контур Codex CLI
0.153.4 с `gpt-5.6-sol` и уровнем рассуждения `xhigh` прошёл итоговый гейт:
23/24 строгих маршрута, 24/24 результата и 24/24 решения о полномочиях.
[Отчёт обо всех 68 попытках](benchmarks/skill-selection-v012/results.md)
публикует также сбои и исправления; это ограниченная диагностика, а не
универсальное утверждение о точности, токенах, стоимости или экономии.

## 🛡️ Экономия без ослабления проверки

Оптимизация считается корректной, только если необходимый результат остаётся эквивалентным и все обязательные проверки проходят. Меньший запуск с худшим результатом — это регрессия, а не экономия. Отсутствующее свидетельство остаётся отсутствующим: STOLZ A.I. никогда не превращает его в ноль.

Реализация описана в разделе [об архитектуре](docs/architecture.md). Набор тестов репозитория проверяет выбор маршрута, неизменяемые идентичности контекста, проверенное повторное использование, устранение дублей операций, переходы тихого состояния и гейты бенчмарка.

```bash
npm test
npm run benchmark:check
```
