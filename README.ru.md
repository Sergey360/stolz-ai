## Что именно экономится

STOLZ A.I. — пять небольших навыков для Codex:

- выбрать один достаточный маршрут, а не загружать все инструкции;
- читать только нужный этому маршруту контекст;
- повторно использовать результат, пока совпадают его входные данные и проверка;
- не переносить неизменные результаты опроса в контекст модели;
- сравнивать оптимизацию с исходным маршрутом до заявления об улучшении.

Эти механизмы сокращают лишний контекст, повторные чтения, вызовы инструментов и сообщения о неизменном состоянии. Они не заставляют модель думать меньше и не отменяют проверки.

## Что уже доказано

В синтетическом примере выбора контекста один и тот же проверенный результат получен за 980 условных токенов вместо 1 530. Это подтверждает работу бенчмарка и маршрута с узким контекстом на конкретном примере.

Это не измерение расхода Codex и не универсальное обещание экономии. Подтверждённых данных о расходе токенов провайдера пока нет. Исходные данные и ограничения описаны в [документе о бенчмарках](docs/benchmarking.md).

## Установка в Codex

Codex находит навыки проекта в `.agents/skills`. Выполните команды из каталога своего проекта:

```bash
git clone https://github.com/Sergey360/stolz-ai.git ../stolz-ai
npm --prefix ../stolz-ai ci
npm --prefix ../stolz-ai test
mkdir -p .agents/skills
cp -R ../stolz-ai/skills/stolz-* .agents/skills/
```

После установки укажите `$stolz-route` в запросе к Codex или позвольте Codex выбрать подходящий навык по описанию. Команды для Windows и установка на уровне пользователя приведены в [инструкции](docs/installation.md).

## Пять навыков

| Навык | Когда использовать |
| --- | --- |
| [`stolz-route`](skills/stolz-route/SKILL.md) | нужно выбрать минимально достаточный маршрут |
| [`stolz-context`](skills/stolz-context/SKILL.md) | контекст нужно проверить и загрузить перед использованием |
| [`stolz-reuse`](skills/stolz-reuse/SKILL.md) | чтение, команда, вызов или результат могут повториться |
| [`stolz-quiet-state`](skills/stolz-quiet-state/SKILL.md) | опрос состояния или повторы создают одинаковые сообщения |
| [`stolz-benchmark`](skills/stolz-benchmark/SKILL.md) | улучшение эффективности нужно сравнить с исходным маршрутом |

## Экономия без ослабления проверки

Оптимизация допустима, только если обязательный результат остаётся эквивалентным и все проверки проходят. Более короткий запуск со слабым результатом — регрессия, а не экономия. Отсутствующие данные остаются отсутствующими: STOLZ A.I. не подменяет их нулём.

Устройство проекта описано в [архитектуре](docs/architecture.md). Тесты проверяют выбор маршрута, идентичность контекста, безопасное повторное использование, объединение одинаковых операций, тихие переходы состояния и правила бенчмарка.

```bash
npm test
npm run benchmark:check
```
