# Optional task brief

Use only when composing an implementation or research request. Fill the
relevant fields; do not attach this template to every coding task.

> Outcome: [observable result and acceptance conditions].
> Scope: [component and intended behavior]; preserve [specific invariants].
> Research, if needed: compare [bounded alternatives] against [criteria], then
> choose and implement one. Stop research when those criteria are answered.
> Local authority: read, edit and run affected checks within this scope; fix
> regressions introduced by the change and rerun failed checks autonomously.
> Decision boundary: ask only for a material scope expansion or an external or
> irreversible action not already authorized. Preserve existing authorization.
> Done: implementation and relevant documentation are complete, affected
> checks pass, introduced failures are fixed, and no known requested part is
> omitted. Include commit/release/deployment evidence if requested. An initial
> patch or an unverified proposal does not satisfy this outcome.

Replace generic test instructions with the component's actual test entry point
and fixture/production boundary. Name uncertainty that needs research rather
than prescribing every search, read and intermediate reasoning step.
